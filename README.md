## **[👉 jinhoops.github.io/stock-snowball](https://jinhoops.github.io/stock-snowball/)**

## 레버리지 상품 비교

가족 바로가기로 `QQQ · QLD · TQQQ`, `AMD · AMDL`, `TSLA · TSLL`, `SOXX · SOXL`을 한 번에 선택할 수 있습니다. 일반 비교 자산은 `SPY`, `SCHD`, `KOSPI 200`, `KOSDAQ`, `GOLD`이며, 전체 정적 카탈로그는 모두 14개입니다. 합성 이력은 만들지 않고 각 상품이 실제로 거래된 데이터만 사용하므로, 비교 기간은 선택한 상품 모두에 존재하는 공통 데이터 기간으로 제한됩니다. 이 때문에 출시가 늦은 상품을 포함하면 5년·10년 같은 기간을 선택하지 못할 수 있습니다.

- `투자 결과`: 기초자금과 설정한 적립금을 함께 반영한 포트폴리오 결과입니다.
- `시작값 100`: 적립금을 제거하고 같은 시작일의 상품 총수익 성과를 100으로 맞춰 비교합니다.
- `명목`: 당시 금액 그대로, `실질`: 설정한 물가상승률 반영, `금 기준`: 시작일 대비 금 가격 변화를 반영한 가치입니다.

선택 기간의 `전고점 회복까지 걸린 시간`은 상품 총수익 지수(배당 재투자, 적립금 제외)에서 최대낙폭을 만든 전고점부터 처음 그 값 이상으로 돌아온 날까지의 **달력 일수**입니다. 끝까지 돌아오지 못했다면 `미회복`과 마지막 관측일까지의 경과일을 표시합니다. 명목·실질·금 기준을 바꾸면 해당 기준으로 다시 계산합니다. `최저점 대비 회복률`은 1년 미만 구간에서 최저점부터 종료일까지 얼마나 반등했는지를 나타내는 별도 지표입니다.

금 기준은 Gold Futures(`GC=F`)를 이용한 대략적인 구매력 비교이며, 물리적 금의 거래 가격이나 비용을 뜻하지 않습니다. `2배·3배는 하루의 목표이며, 전체 기간 수익률의 약속이 아닙니다.` 장기 결과는 변동성, 복리 경로, 상품 비용과 추적 차이 때문에 기초자산 수익률의 단순 2배·3배와 크게 달라질 수 있습니다.

상품 성과 지표와 레버리지 해설은 세전입니다. 적립식 포트폴리오 결과에는 설정한 매수 수수료와 ISA 만기 세금 추정치만 포함하며, 매도 수수료·배당세·일반계좌 양도소득세는 계산하지 않습니다. 펀드 보수와 실제 추적 결과는 거래 가격에 이미 반영된 것으로 보고 별도로 다시 차감하지 않습니다.

## 계산 기준과 한계

미래 시뮬레이션의 수익률·물가·환율 변화율은 연 유효율이며, 1년을 365일로 계산합니다. 시작점에는 초기 원금만 넣고 이후 평일·월요일·매월 1일 중 선택한 주기로 납입합니다. 시장 공휴일은 별도로 반영하지 않습니다. 가치 분할 매수는 월간 목표로 계산합니다. 낙관·비관선은 변동성 가정을 보여 주는 예시이며 검증된 90% 신뢰구간이 아닙니다.

백테스트는 실제 데이터 날짜를 사용하고 첫 날짜에 초기 원금과 첫 적립금을 함께 넣습니다. 배당락일 이전 보유 수량에만 배당을 지급하며, 재투자하지 않은 배당은 현금으로 유지합니다. 상품 CAGR과 포트폴리오 IRR은 구분하고 날짜 기반 연환산에는 365.25일을 사용합니다. 과거 참조 수익률은 배당 포함 전체 이력 CAGR이며, 변동성은 표본 일 표준편차의 `sqrt(252)` 연환산입니다.

미래 시뮬레이션은 매수·매도 수수료와 세금 추정치를 포함하며, 일반계좌 세금은 양의 전체 이익에 배당세율을 적용하는 단순 모델입니다. ISA 기본값은 공제 200만원·초과분 9.9%이고 저장된 설정은 유지합니다. 백테스트의 비용·세금 범위는 위 설명처럼 다릅니다. 포트폴리오 IRR은 실제 납입 날짜와 종료 가치를 사용하며, 연환산할 수 없는 결과는 0%로 대신 표시하지 않습니다.

2026-09-10 계산 오류 수정과 독립 검산은 [계산 신뢰도 점검 보고서](docs/calculation-audit.md)에 기록했습니다. 당시 남았던 국내 거래일 불일치와 종가 차이는 2026-09-28에 출처를 대조해 보정했으며, 근거와 갱신 범위는 [시장 데이터 갱신 보고서](docs/market-data-refresh-2026-09-28.md)에서 확인할 수 있습니다.

## 백테스트 데이터 갱신

시세는 GitHub Actions가 매일 한국 시간 10:17에 수집·검증하여 Supabase Storage에 게시합니다. 브라우저는 공개 CSV와 JSON 매니페스트를 내려받아 기기에 보관하며 외부 시세 제공자 API를 직접 호출하지 않습니다. 일반 갱신에는 로컬 PC, 데이터 커밋·푸시, 앱 재배포가 필요하지 않습니다. 현재 커밋된 CSV는 오프라인 기본 데이터와 독립 계산 검산 기준으로 유지합니다. 기존의 투자·백테스트용 일별 이력 14개는 그대로 유지합니다: `QQQ`, `QLD`, `TQQQ`, `AMD`, `AMDL`, `TSLA`, `TSLL`, `SOXX`, `SOXL`, `SPY`, `SCHD`, `KOSPI` (`^KS200`), `KOSDAQ` (`^KQ11`), `GOLD` (`GC=F`).

시장 추세는 투자 대상이 아닌 보조 문맥 데이터입니다. `^NDX`(나스닥100), `^GSPC`(S&P 500), `^KS11`(코스피)의 세 주간 벤치마크는 포트폴리오에 편입하거나 수익률을 비교하는 용도가 아닙니다. 화면의 시장 오버레이는 선택한 **주 자산**만 따르며, 포트폴리오 수익률 비교가 아닌 가격지수의 추세를 보여 줍니다.

갱신 스크립트는 Yahoo Finance에서 일별 데이터를 내려받지만, 세 시장 벤치마크는 완료된 주의 마지막 종가만 주별 CSV로 게시합니다. 주별 끝점은 고정된 `exchange_calendars` 거래소 달력으로 검증하므로 정상 영업 주의 목요일 데이터만으로 금요일 종가를 대신할 수 없고, 휴장으로 목요일이 실제 마지막 거래일인 주는 허용됩니다. 20주·60주 SMA도 이 완료 주봉만 사용하므로 진행 중인 주의 값이나 부분 주간 데이터가 미래를 미리 반영하지 않습니다.

2026년 7~9월 KOSPI 200과 8~9월 KOSDAQ의 검토된 누락·종가 보정 행은 Naver Finance 종가와 조회 시각·URL을 매니페스트에 함께 보관하고, 갱신 때 결정적으로 재적용합니다. 오프라인 검사는 이 값과 긴 미승인 데이터 공백을 검증하고, 두 국내 지수는 2026-08-28 이후 완료된 XKRX 거래일의 누락도 검사합니다. 새 갱신본이 이미 커밋된 일별 거래일을 조용히 삭제하면 원자적 교체 전에 중단합니다. 외부 시세 제공자 조회는 전용 데이터 workflow 또는 수동 수집 명령에서만 일어납니다. 앱 빌드·프런트엔드 검사는 외부 시세 통신을 요구하지 않습니다.

Python은 승인된 3.13 계열을 사용합니다. `.python-version`의 `3.13`과 `pyproject.toml`의 범위에 따라 `uv`가 사용 가능한 최신 3.13 패치 버전을 설치·선택합니다.

```bash
uv python install 3.13
uv sync --locked
npm run data:refresh # 외부 시세를 수동 조회해 14개 투자 자산과 주별 시장 벤치마크를 갱신
npm run data:check   # 외부 통신 없이 커밋된 CSV·매니페스트를 검증
npm test
npm run build
```

시세는 실제 종목·지수의 제공 가능한 기간만 사용합니다. 투자 자산 생성 데이터는 분할 조정 종가와 별도 현금 배당을 보관하고, 시장 벤치마크는 완료 주봉 종가만 보관합니다. 갱신은 14개 투자 CSV, 세 개의 작은 주별 벤치마크 CSV, schema-4 매니페스트를 모두 검증한 뒤 원자적으로 교체하므로 일부 종목만 성공한 결과를 남기지 않습니다. 일상 갱신은 원격 마지막 정상 버전에서 이어서 수집하고 새 버전으로 게시합니다. 동봉 CSV를 갱신하는 예외 작업만 검토 후 커밋합니다.

증분 갱신의 새 행에서 주식 분할이 발견되면 서로 다른 조정 기준이 섞이지 않도록 중단합니다. 이 경우 전체 이력을 다시 생성해야 하며, 자동으로 원본 CSV를 덮어쓰지는 않습니다.


### 자동 갱신 운영

전용 버킷은 `stock-snowball-market-data`입니다. 공개 읽기만 사용하며 클라이언트에 API 비밀값을 넣지 않습니다. GitHub 저장소의 Actions variable `SUPABASE_URL`과 Actions secret `SUPABASE_SERVICE_ROLE_KEY`를 설정합니다. 서버 키는 `VITE_*`, Git, 로그, artifact에 넣지 않습니다.

`Refresh market data` workflow는 기본 브랜치에서 매일 `01:17 UTC`에 실행합니다. 시세 날짜는 전날 UTC 날짜까지 제한하고, 주봉 완료 여부는 실제 수집일로 판단합니다. 새 schema-4 매니페스트의 선택 필드 `dataThrough`가 날짜 상한을 기록합니다. `generatedAt`은 수집·판정 시각, `publishedAt`은 게시 시각, 자산별 `endDate`는 실제 데이터 기준일입니다. 거래일이 전혀 없는 일별 증분 구간은 시세 제공자에 조회하지 않습니다.

Actions에서 수동 실행할 때 모드를 선택합니다.

| 모드 | 동작 |
| --- | --- |
| `refresh` | 원격 마지막 정상 버전에서 증분 수집·검증·게시. 일반 재실행도 이 모드 |
| `bootstrap` | 최초 1회 동봉 카탈로그 게시. 이미 최신 포인터가 있으면 거부 |
| `publish` | 검토·수정한 완성 카탈로그 게시. 기본 브랜치의 동봉 CSV를 사용하고 날짜 보존 검증 |
| `rollback` | `release_id`로 지정한 보관 버전 전체를 검증한 뒤 최신 포인터만 복원 |

```bash
# 운영자는 GitHub Actions에서 실행하는 것을 우선합니다.
gh workflow run refresh-market-data.yml -f mode=refresh
gh workflow run refresh-market-data.yml -f mode=rollback -f release_id=보관된_버전_ID
# 로컬 도구는 상속된 서버 환경 변수를 사용합니다. .env를 자동으로 읽지 않습니다.
npm run data:sync -- --mode refresh
# 분할 등 예외에서 전체 카탈로그를 별도 경로에 재생성·검토한 경우:
npm run data:sync -- --mode publish --data-dir /absolute/path/to/reviewed-catalog
```

새 버전은 `v1/releases/<releaseId>/`에 CSV·manifest·해시 목록을 변경 불가능하게 올리고 공개 URL로 확인한 뒤 `v1/latest.json`을 교체합니다. 실제 게시된 버전의 `published.json` 기록을 기준으로 최근 10개를 보관하고 current·previous는 항상 남깁니다. 실패한 업로드 폴더는 정상 보관 개수에 포함하지 않습니다. 중간 오류는 마지막 정상 버전을 유지합니다. 포인터의 CDN 캐시는 최대 60초이며 잠깐 구 버전이 보여도 전체 카탈로그의 일관성은 유지됩니다. 모든 운영 모드는 하나의 workflow concurrency 그룹으로 직렬화합니다. 로컬 게시 도구를 workflow와 동시에 실행하지 않습니다.

앱은 완전한 IndexedDB 캐시 또는 동봉 CSV로 시작합니다. 새 데이터는 전체 검증·저장 뒤 「새로고침해 적용」으로 사용하며, 사용 중인 페이지의 결과를 몰래 바꾸지 않습니다. 캐시는 별도 `stock-snowball-market-data` DB에 두고 저장된 시나리오 DB와 분리합니다. 기본 환율·물가·세금은 이 자동 수집 대상이 아니며 사용자 설정도 덮어쓰지 않습니다.

GitHub workflow 실패 알림을 켜고 요약에서 자산별 종료일과 releaseId를 확인합니다. 공개 저장소는 60일 무활동 시 예약 실행이 중단될 수 있고 Free Supabase는 DB 저활동 시 일시정지될 수 있습니다. Storage 접근만으로 휴면을 막는다고 보장하지 않습니다. 실행 자체가 중단되면 실패 알림도 발생하지 않으므로 장기 무관리 운영에는 외부 감시 또는 별도 스케줄러를 검토합니다. 국내 지수의 Yahoo 누락은 기존 Naver 참조 출처로 제한적으로 보충합니다. KOSPI 200·KOSDAQ 모두 이전 정상 카탈로그와 겹치는 값 3개 이상을 대조하고, Naver 코스피와 최근 Yahoo ^KS11 이력도 3개 이상·최대 14일 이내로 교차 대조합니다(허용 차이 지수 0.02). 이번에 보충한 행·URL·조회 시각·대조 날짜와 오차는 매니페스트의 source.automaticDailyBackfills에 기록하고 CSV와 함께 재검증합니다. 당일 장중 행은 제외하며 어느 검증이든 실패하면 전체 게시를 중단합니다. 주식 분할·출처 불일치 등 검토가 필요한 예외에서는 마지막 정상 버전을 유지하고 임의 보간하지 않습니다.
