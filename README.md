# ❄️ Stock Snowball

## **[👉 jinhoops.github.io/stock-snowball](https://jinhoops.github.io/stock-snowball/)**

## 레버리지 상품 비교

가족 바로가기로 `QQQ · QLD · TQQQ`, `AMD · AMDL`, `TSLA · TSLL`, `SOXX · SOXL`을 한 번에 선택할 수 있습니다. 일반 비교 자산은 `SPY`, `SCHD`, `KOSPI 200`, `KOSDAQ`, `GOLD`이며, 전체 정적 카탈로그는 모두 14개입니다. 합성 이력은 만들지 않고 각 상품이 실제로 거래된 데이터만 사용하므로, 비교 기간은 선택한 상품 모두에 존재하는 공통 데이터 기간으로 제한됩니다. 이 때문에 출시가 늦은 상품을 포함하면 5년·10년 같은 기간을 선택하지 못할 수 있습니다.

- `투자 결과`: 기초자금과 설정한 적립금을 함께 반영한 포트폴리오 결과입니다.
- `시작값 100`: 적립금을 제거하고 같은 시작일의 상품 총수익 성과를 100으로 맞춰 비교합니다.
- `명목`: 당시 금액 그대로, `실질`: 설정한 물가상승률 반영, `금 기준`: 시작일 대비 금 가격 변화를 반영한 가치입니다.

금 기준은 Gold Futures(`GC=F`)를 이용한 대략적인 구매력 비교이며, 물리적 금의 거래 가격이나 비용을 뜻하지 않습니다. `2배·3배는 하루의 목표이며, 전체 기간 수익률의 약속이 아닙니다.` 장기 결과는 변동성, 복리 경로, 상품 비용과 추적 차이 때문에 기초자산 수익률의 단순 2배·3배와 크게 달라질 수 있습니다.

상품 성과 지표와 레버리지 해설은 세전입니다. 적립식 포트폴리오 결과에는 설정한 매수 수수료와 ISA 만기 세금 추정치만 포함하며, 매도 수수료·배당세·일반계좌 양도소득세는 계산하지 않습니다. 펀드 보수와 실제 추적 결과는 거래 가격에 이미 반영된 것으로 보고 별도로 다시 차감하지 않습니다.

## 계산 기준과 한계

미래 시뮬레이션의 수익률·물가·환율 변화율은 연 유효율이며, 1년을 365일로 계산합니다. 시작점에는 초기 원금만 넣고 이후 평일·월요일·매월 1일 중 선택한 주기로 납입합니다. 시장 공휴일은 별도로 반영하지 않습니다. 가치 분할 매수는 월간 목표로 계산합니다. 낙관·비관선은 변동성 가정을 보여 주는 예시이며 검증된 90% 신뢰구간이 아닙니다.

백테스트는 실제 데이터 날짜를 사용하고 첫 날짜에 초기 원금과 첫 적립금을 함께 넣습니다. 배당락일 이전 보유 수량에만 배당을 지급하며, 재투자하지 않은 배당은 현금으로 유지합니다. 상품 CAGR과 포트폴리오 IRR은 구분하고 날짜 기반 연환산에는 365.25일을 사용합니다. 과거 참조 수익률은 배당 포함 252개 일 수익률 구간의 중앙값, 변동성은 표본 일 표준편차의 `sqrt(252)` 연환산입니다.

미래 시뮬레이션은 매수·매도 수수료와 세금 추정치를 포함하며, 일반계좌 세금은 양의 전체 이익에 배당세율을 적용하는 단순 모델입니다. ISA 기본값은 공제 200만원·초과분 9.9%이고 저장된 설정은 유지합니다. 백테스트의 비용·세금 범위는 위 설명처럼 다릅니다. 포트폴리오 IRR은 실제 납입 날짜와 종료 가치를 사용하며, 연환산할 수 없는 결과는 0%로 대신 표시하지 않습니다.

2026-09-10 계산 오류 수정, 독립 검산과 미확정 데이터 사항은 [계산 신뢰도 점검 보고서](docs/calculation-audit.md)에 기록했습니다. 국내 최근 일부 날짜의 달력 대조 불일치는 원인이 미확정이며, 이번 점검에서는 시세 CSV를 갱신하지 않았습니다.

## 백테스트 데이터 갱신

백테스트 데이터는 브라우저와 배포 CI가 외부 시세 API를 호출하지 않도록 정적 CSV와 JSON 매니페스트로 커밋해 제공합니다. 기존의 투자·백테스트용 일별 이력 14개는 그대로 유지합니다: `QQQ`, `QLD`, `TQQQ`, `AMD`, `AMDL`, `TSLA`, `TSLL`, `SOXX`, `SOXL`, `SPY`, `SCHD`, `KOSPI` (`^KS200`), `KOSDAQ` (`^KQ11`), `GOLD` (`GC=F`).

시장 추세는 투자 대상이 아닌 보조 문맥 데이터입니다. `^NDX`(나스닥100), `^GSPC`(S&P 500), `^KS11`(코스피)의 세 주간 벤치마크는 포트폴리오에 편입하거나 수익률을 비교하는 용도가 아닙니다. 화면의 시장 오버레이는 선택한 **주 자산**만 따르며, 포트폴리오 수익률 비교가 아닌 가격지수의 추세를 보여 줍니다.

갱신 스크립트는 Yahoo Finance에서 일별 데이터를 내려받지만, 세 시장 벤치마크는 완료된 주의 마지막 종가만 주별 CSV로 커밋합니다. 주별 끝점은 고정된 `exchange_calendars` 거래소 달력으로 검증하므로 정상 영업 주의 목요일 데이터만으로 금요일 종가를 대신할 수 없고, 휴장으로 목요일이 실제 마지막 거래일인 주는 허용됩니다. 20주·60주 SMA도 이 완료 주봉만 사용하므로 진행 중인 주의 값이나 부분 주간 데이터가 미래를 미리 반영하지 않습니다.

Yahoo Finance가 누락한 2026년 7~8월 KOSPI 200 일별 구간은 수동 검토한 Naver Finance 종가와 조회 시각·URL을 매니페스트에 함께 보관하고, 수동 갱신 때 결정적으로 재적용합니다. 오프라인 검사는 이 값과 긴 미승인 데이터 공백을 검증하며, 새 갱신본이 이미 커밋된 일별 거래일을 조용히 삭제하면 원자적 교체 전에 중단합니다. 외부 시세 제공자 조회는 개발자가 아래 명령으로 수동 갱신할 때만 일어나며, 브라우저와 CI는 실행 중 외부 시세 API를 호출하지 않습니다.

Python은 승인된 3.13 계열을 사용합니다. `.python-version`의 `3.13`과 `pyproject.toml`의 범위에 따라 `uv`가 사용 가능한 최신 3.13 패치 버전을 설치·선택합니다.

```bash
uv python install 3.13
uv sync --locked
npm run data:refresh # 외부 시세를 수동 조회해 14개 투자 자산과 주별 시장 벤치마크를 갱신
npm run data:check   # 외부 통신 없이 커밋된 CSV·매니페스트를 검증
npm test
npm run build
```

시세는 실제 종목·지수의 제공 가능한 기간만 사용합니다. 투자 자산 생성 데이터는 분할 조정 종가와 별도 현금 배당을 보관하고, 시장 벤치마크는 완료 주봉 종가만 보관합니다. 갱신은 14개 투자 CSV, 세 개의 작은 주별 벤치마크 CSV, schema-4 매니페스트를 모두 검증한 뒤 원자적으로 교체하므로 일부 종목만 성공한 결과를 남기지 않습니다. 생성된 CSV와 매니페스트 변경 사항을 검토한 후 함께 커밋합니다.

증분 갱신의 새 행에서 주식 분할이 발견되면 서로 다른 조정 기준이 섞이지 않도록 중단합니다. 이 경우 전체 이력을 다시 생성해야 하며, 자동으로 원본 CSV를 덮어쓰지는 않습니다.
